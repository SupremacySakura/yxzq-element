# 组件库范围:核心子集、约 30 个

在规划"补全组件库"时，我们放弃了对标 Element Plus / Ant Design 全集(60–70+ 个)的做法,改为实现约 30 个核心组件。原因:本仓库是手绘风原创组件系统(见 AGENTS.md),不应复制 Element Plus API;60+ 组件对单人维护不现实;30 个左右的核心集能在"覆盖常见应用场景"与"可持续维护"之间取得平衡。

## Considered Options

- **A. 对标 Element Plus 全集**:拒绝。违背"不复制 Element Plus"的项目方向,且工作量超出可持续维护范围。
- **C. 由具体产品需求驱动,按需添加**:拒绝。会让组件集长期处于"残缺"状态,无法构成可发布的完整库。

## Consequences

- 候选组件清单需要逐一明确,并以"哪些不做"为显式决策(见后续 ADR)。
- 任何新增组件都必须满足 ADR-0002 的深度契约与 ADR-0003 的同步契约。
